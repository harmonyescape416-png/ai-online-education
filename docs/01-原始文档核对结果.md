## 3. 系统设计说明书核对（接口 / SSE / Redis / AI 流程）

**接口清单（5.2.3，27 条，原文照录）**：`/auth/login`、`/auth/logout`、`/users/me`、`/courses`、`/courses/{id}`、`/courses/search`、`/session`(POST)、`/session/hot`、`/chat`(POST,SSE)、`/chat/stop`、`/chat/text`、`/chat/templates`、`/session/{sessionId}`、`/session/history`(GET/DELETE/PUT)、`/courses/{id}/ai`、`/orders/pre-place`、`/audio/tts-stream`、`/audio/stt`、`/embedding`(POST/GET)、`/questions`(POST/GET)、`/questions/{id}`、`/questions/{id}/replies`、`/eval/cases`、`/eval/run`、`/eval/summary`。

统一返回 `R<T>`：`code / msg / data / requestId`；SSE 接口用 `@NoWrapper`，返回 `Flux<ChatEventVO>`。

**SSE 协议（3.1.4、4.2）**：`text/event-stream`，事件负载 JSON；`1001` 文本增量（`data.content`）、`1003` 参数事件（课程/订单卡片）、`1002` 结束事件；客户端收到 1002 后关闭连接。
> 实现约束：`/chat` 是 **POST** + SSE，`EventSource` 不支持 POST，前端必须用 `fetch + ReadableStream` 自行解析 SSE 帧。

**Redis 缓存策略（第 8 章）**

| 缓存内容 | 键 | TTL | 失效策略 |
|---|---|---|---|
| 会话消息 | `CHAT:{conversationId}`，`conversationId = userId + "_" + sessionId` | 7 天 | 删除会话/停止补写 |
| 停止标识 | `AI:STOP:{sessionId}` | 5 分钟 | 生成结束删除 |
| 提示词/热门问题 | Nacos 配置（`tj.ai.session`） | 长驻 | 监听热更新 |
| 会话标题 | `chat_session.title`（DB） | — | 异步更新 |
| 课程热点 | `course:{id}` | 10 分钟 | 课程更新删除 |
| 评测汇总 | `eval:summary` | 30 分钟 | 批次完成刷新 |

降级：Redis 不可用→会话记忆降级为无记忆、停止标识降级本地状态；ES 不可用→RAG 降级为无知识库并提示；Nacos 不可用→本地缓存提示词并告警。

**AI 业务流程（4.2~4.7）**：前端 POST `/chat` → 网关鉴权 → aigc 生成 conversationId → 加载提示词与记忆 → RouteAgent **非流式**判断意图 → 分发 RECOMMEND/BUY/CONSULT/KNOWLEDGE → 需要时调用 CourseTools(CourseClient) / OrderTools(TradeClient) / RAG → 工具执行前从 ToolContext 取 userId 并重设 UserContext（避免 Feign 401）→ 结果暂存 `ToolResultHolder` → 流结束组装 1003 → SSE 返回 → 保存记忆并异步更新标题。
自动回复：学员提问落 `interaction_question` → learning 异步调 aigc `/chat/text` → 写入 `interaction_reply`（**系统用户 9999，is_student=0**）→ 更新问题的 `latest_answer_id / answer_times`。
`RecordOptimizationAdvisor` 负责清理路由产生的两条临时消息。

## 4. 数据库设计说明书核对（12 张表 / 150 字段）

建表 SQL 已**逐字还原**到 `sql/01_schema.sql`（第 5.2.1~5.2.12 节），已在 MySQL 8.0.35 执行成功：

`user`(10) `course_category`(8) `course`(20) `course_content`(10) `course_chapter`(8) `order`(19) `order_detail`(18) `interaction_question`(14) `interaction_reply`(14) `chat_session`(8) `ai_eval_case`(11) `learning_lesson`(10) = 12 张 / 150 字段。

关键约定：主键 BIGINT 雪花算法（无 AUTO_INCREMENT）；金额 INT 分；状态 TINYINT；`course_content.id = course.id`；微服务间逻辑外键、不建物理外键；`deleted` 逻辑删除。
会话消息设计：**不落 MySQL**，`chat_session` 只存元数据，消息存 Redis 列表 `CHAT:{conversationId}`（5.4.2、7.1）。

## 5. 文档间差异、修正与扩展设计

### 5.1 原文内部冲突（按 DB 说明书为准，明确记录）

| 冲突点 | 需求分析说明书 | 数据库/系统设计说明书 | 处理方式 |
|---|---|---|---|
| 课程状态枚举 | 3.3(7)：草稿、待审核、已上架、已下架 | DB 3.3.3：1待上架，2已上架，3下架，4已完结 | **以 DB 为准**；「草稿」与「待审核」归入 `status=1 待上架`，区分靠审核记录表（见 5.3 扩展） |
| 订单状态 | 3.2.3.4：待支付、已支付、已取消 | DB 3.3.6：1待支付，2已支付，3已关闭，4已完成，5已报名，6已申请退款 | **以 DB 为准**；「已取消」映射 `status=3 已关闭` |
| 角色取值 | 3.3(2)：管理员/教师运营/学员 + AI 系统账号 | DB 3.3.1：`type` 1员工，2学员，3老师 | 映射 **1=员工(管理员/运营)、2=学员、3=老师**；AI 系统账号 `id=9999`、`type=1` |

### 5.2 此前计划的修正

- 原计划「token 失效」仅靠过期 → 修正：需求 3.2.1.1 与 3.3(8) 要求**禁用/退出后立即失效**，需 Redis 黑名单或 token 版本校验（见 5.3 扩展 E1）。
- 原计划把课程「草稿/待审核」当独立状态 → 修正为 `status=1`，审核结论存扩展表。
- 原计划 SSE 用 `EventSource` → 修正为 `fetch + ReadableStream`（`/chat` 为 POST）。
- 技术版本以此前「自行指定」为准的部分 → 统一改为**原始设计版本**（见第 6 节）。
