# 学员学习计划

2026-10-23。学习计划不是「我的学习」里的累计进度。周完成量只认首次完课事实。

## 规则

- 时区 Asia/Shanghai。一周从周一开始，区间是 `[周一 00:00, 下周一 00:00)`。
- 本周完成量：`learning_first_event` 中 `CHAPTER_FINISH`，业务日落在本周，完成时刻不早于加入时间，不晚于退出时间，并且不落在暂停区间。重复上报同一章节不会再插入首次事件，因此不会重复计数。
- 中途加入：加入时刻之前的完成不计入这个计划，包括本周早些时候已经完成的章节。
- 修改目标：写入下一周的目标。本周和更早的周保持当时生效的目标。
- 暂停：暂停到恢复之间的首次完成不计入。恢复不改本周目标。
- 退出：计划结束。再次加入会新建一条计划，不改旧计划。
- 同一学员、同一课程，进行中和暂停只能有一条。重复加入返回原计划，`alreadyJoined=true`。数据库唯一键 `uk_plan_open` 防止两条有效计划。
- 课程章节全部首次完成后，计划变为「课程已完成」，不再提供计划内的继续学习入口。
- 退款、到期或课程不可访问时保留计划，但 `canContinue=false`，并显示权益原因。
- `learning_fact_coverage.facts_since` 所在业务日晚于本周周一时，本周完成量为 null，并说明不能把缺失记成 0。不回填迁移前的周数据。
- 身份只取认证上下文。学员不能操作别人的计划。教师统计接口没有改动。

## 演示步骤

服务更新并执行迁移之后：

1. 用 student01 登录，打开「我的学习」，进入「查看学习计划」。
2. 选择一门已有学习资格的课程，每周目标设为 2，加入。刷新后计划仍在。
3. 再点一次加入，应提示已经在计划中，不产生第二条。
4. 把目标改成 5。本周仍显示 2，并提示下周改为 5。
5. 本周首次完成 1 节后，显示已完成 1、剩余 1、比例 50%。再上报同一节，数量不变。
6. 暂停后完成的章节不增加本周数量。恢复后新的首次完成才会计入。
7. 退出后计划从进行中消失。再次加入是一条新计划。
8. 退款或权益到期后，计划还在，但没有「继续学习」，并显示原因。
