# 支付与退款

2026-10-23。订单仍由服务端计算金额。支付成功只来自验签通过的通知，不来自前端跳转、支付按钮或模型回复。

## 渠道

| 模式 | 状态 |
|---|---|
| MOCK | 已用 H2 测试验证。微信、支付宝两个入口在未配置沙箱时都走模拟渠道，分别记为 `MOCK_WECHAT`、`MOCK_ALIPAY`。签名是本系统的 HMAC，不是微信或支付宝算法。 |
| 支付宝沙箱 | 验签代码按支付宝开放平台「异步通知说明」的 RSA2 步骤实现：去掉 `sign`、`sign_type` 和空值，参数名 ASCII 排序后做 SHA256WithRSA。沙箱网关地址为 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`。本环境没有 `ALIPAY_SANDBOX_*` 密钥，没有向沙箱发起下单或退款。`sandboxAccepted=false`。 |
| 真实渠道 | 未接入，未发生真实资金交易。 |

## 规则

- 重复通知只入账一次，不重复登记开课补偿。
- 验签失败或金额、币种不一致时，订单保持原状态。
- 超过 30 分钟未支付会被条件更新为关闭。若之后收到已验签的成功通知，超时关闭可以恢复为已支付；用户主动取消的订单不会被恢复。
- 支付成功后仍走原来的开课补偿。开课失败不把支付改回未支付。
- 退款按课程明细的实付金额，不按课程原价。部分退款未退完时保留该课程权益；全部退完才收回。申请中暂停权益，驳回或渠道失败后恢复。
- 同一 `requestId` 重复申请返回原退款单。处理中的明细不能再开第二张退款单。
- 优惠券见 `docs/96-优惠券.md`。退款金额按明细实付，不按原价。已核销的券在部分退款和全额退款后都不退回。
- 学员订单列表的「退款结果」只显示最新一条「已通过」或「已驳回」。已驳回在同一处带驳回原因。退款成功的明细上，「申请退款」为不可点击。渠道退款成功或明细已退完时，订单状态列显示「已退款」，样式与其他订单状态标签相同。
