# 优惠券

2026-10-23。优惠券放在交易服务里，和订单使用同一个事务边界。金额单位是分。每笔订单只能使用一张券，不展示叠券。

## 规则

- 满减券按门槛和减免额计算。折扣券的 `payRatio` 是支付比例的万分比，8500 表示支付 85%。优惠额按分四舍五入（HALF_UP）。
- 指定课程时，只把适用课程的价格计入门槛和优惠，再按最大余数分摊。各明细优惠之和等于订单优惠。
- 领取时把规则抄到用户券上。之后修改模板不会改变已领取的券。已发布模板不能再编辑，只能停止发放。
- 领取时间是闭开区间 `[claimStart, claimEnd)`，使用时间是 `[validStart, validEnd)`。
- 库存用 `claimed_count < total_stock` 条件更新。每人限领用 `(template_id, user_id, slot_no)` 唯一键。兑换码再用 `(template_id, user_id, code_claim)` 保证同一用户不能重复兑换。
- 下单锁定券，支付成功核销，取消或超时关闭释放。重复支付只核销一次。
- 超时关闭后又收到已验签的成功支付时，会尝试重新核销。券若已被别的订单占用，支付仍然入账，并写入 `mkt_coupon_compensate`，由定时任务重试。
- 部分退款和全额退款都不退券。可退金额是明细实付减去已成功退款，不是课程原价。

`CouponFlowTest` 3 项通过：最后一张券两个并发领取只有一个成功、重复兑换、快照不被模板修改影响、下单锁定、重复核销、退款不退券、取消释放、核销失败后的补偿重试。

并发领取跑在 H2，不是 MySQL，也不是支付宝沙箱。
