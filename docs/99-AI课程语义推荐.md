# AI 课程语义推荐交付与验收（2026-10-23）

本次在现有 Spring AI、课程、学习、交易和 Vue 架构内增加了真实课程推荐链路。课程推荐使用独立 Embedding 配置与 ES 索引，教师资料知识库继续按原配置运行。推荐工具只读；下单仍经过原有服务端购买确认门禁。

## 推荐链路

1. 用户可在 AI 工作台展开“按学习目标选课”，也可在对话中描述目标。主题不明时仅追问学习目标；基础、单门预算、每周时间和周期均可跳过。
2. 条件保存在当前用户的当前会话。修改部分条件可保留其余条件；`clearBudget/clearTime/clearCategory` 撤销条件。页面按当前表单重设时间条件，清空单个时间字段不会沿用旧值。
3. 真实 Embedding 将目标向量化，从独立课程索引召回最多 20 项；课程服务关键词查询最多 10 项。按课程 ID 去重，以 RRF `1/(60+rank)` 累加排序，同分按 ID 排序。
4. 课程服务逐项复核当前上架、分类启用、删除、销售时间、价格和购买资格。按预算、二级分类、公开适用人群、已登记视频时长筛选。课程索引里的快照不作为交易事实。
5. 通过可信身份查询当前用户学习记录和已支付课程，默认排除已购、已加入学习及已完成课程；明确包含时返回真实状态，并禁用卡片重复购买按钮。读取个人记录失败会返回 `PROFILE_UNAVAILABLE`，不会假装用户从未购买。
6. 卡片展示课程服务返回的名称、价格、有效期、简介及适用人群原文依据。视频时长或适用基础不明确时显示限制，不补造时长、效果或就业承诺。
7. 咨询和选择课程按钮只回填带真实 ID 的问题，用户发送后进入原有咨询或购买智能体。推荐与兴趣表达不构成购买确认；`PurchaseProposalStore/OrderTools` 仍核对当前课程、确认提案和幂等号，未增加直接支付路径。

推荐智能体只获 `recommendCourses/getCourseDetail`，关键词召回在推荐服务内部完成，避免模型直接走旧查课工具而绕过条件与已购排除。咨询、知识问答、路由和购买智能体保持原有权限边界。工具调用记录受控状态、耗时和结果数，不记录用户原文或密钥。

`retrievalMode` 含义：`HYBRID`=语义和关键词均贡献候选；`SEMANTIC`=语义检索完成（不保证一定有结果）；`KEYWORD_ONLY`=仅有关键词候选或 Mock 模式；`KEYWORD_FALLBACK`=语义故障后关键词降级；`NONE`=需要澄清；`UNAVAILABLE`=课程源不可用。界面和工具都明确展示降级，Mock 向量不作为语义质量证据。

## 课程索引与失败补偿

源接口只返回公开课程名称、简介、适用人群、章节标题/顺序及公开展示字段。向量文本白名单不包含受保护正文、教师附件、内部文件路径或个人学习记录。章节标题是目前实际具备的公开章节信息，没有生成或臆造章节摘要。

目录采用持久化分页对账：默认每 5 秒扫描 50 个课程 ID，完整扫描后重新开始，涵盖新增、编辑、上架、下架、逻辑删除及物理删除。扫描游标使用事务行锁跨实例串行提交，源请求失败不前移游标、不误判删除。相同内容指纹不产生重复任务；变化则递增课程任务版本。

后台每秒尝试一批 3 个任务，通过条件更新租约防止多实例重复领取。失败指数退避，最多 5 次后为 `FAILED`，可管理员重试。任务完成回执同时比较版本和租约。ES 写入使用严格 external version，同版重试和旧版写入不能覆盖新版。下架/删除保留不可见墓碑，避免 ES 删除版本回收后旧任务复活。管理重建同样递增版本，不通过清空索引重置版本。

这是**最终一致的目录对账**，不是同步事件或零延迟索引更新。正常扫描等待约为 `(ceil(课程数/50)+1)*5秒` 加后台队列时间；网络失败、积压和重试会延长。旧索引即使暂未更新，实时课程复核仍拒绝已下架或不可购买课程。新增课程需等首次索引任务成功后才能语义召回，关键词可以先查到。

索引命名为 `kzai-course-recommend-<hash>`，hash 包含提供方、模型名、真实返回维度和公开文档版本。不同模型或维度生成独立命名空间和独立同步任务，不复用教师知识库别名；旧空间不自动删除。升级模型时先初始化新空间并评测，保留旧配置以便回切；不要只删除任务表后继续向原索引写入从 1 开始的版本。

## 迁移与部署

先执行 `sql/23_m23_course_recommendation.sql`（同内容在 `deploy/migrations/V20261030_course_recommendation.sql`）。只新增同步游标、索引任务和会话偏好三张表，`CREATE TABLE IF NOT EXISTS` 可重复执行。推荐偏好随会话删除事务清理。

| 配置 | 默认 | 说明 |
|---|---|---|
| `KZAI_RECOMMENDATION_EMBEDDING_PROVIDER` | `mock` | 真实语义推荐设为 `dashscope`，缺 Key 时启动报错 |
| `KZAI_RECOMMENDATION_EMBEDDING_MODEL` | `text-embedding-v4` | 推荐专用，不更改 `KZAI_EMBEDDING_MODEL` |
| `DASHSCOPE_API_KEY` | 空 | 通过运行环境或私有配置注入 |
| `DASHSCOPE_ENABLED` | `false` | 真实对话/路由需开启；推荐面板的真实 Embedding 独立选择 |
| `KZAI_RECOMMENDATION_INDEXING_ENABLED` | `true` | 自动初始化与持续对账 |
| `KZAI_RECOMMENDATION_INDEX_PREFIX` | `kzai-course-recommend` | 必须为课程推荐独立前缀 |
| `KZAI_RECOMMENDATION_MIN_SCORE` | `0.78` | ES cosine `_score=(1+cosine)/2`，不是相关概率 |
| `KZAI_ES_URL` | `http://127.0.0.1:9200` | 复用现有 ES 连接，使用独立索引 |

本机已应用迁移并启用推荐专用 DashScope v4；教师资料 Embedding 配置未改为真实模型。密钥和原运行参数保存在被忽略的 `.runtime/services/kzai-aigc/runtime-env.json`，权限 600，`scripts/run-services.sh` 启动该服务时加载；文档、源码、评测文件不含密钥。其他部署通过环境变量注入，Compose 已补齐对应配置。

最终检查命名空间 `kzai-course-recommend-18df39c315a6fe85` 的 289 个目录任务全部 READY（包含不可见课程墓碑，不代表 289 门可购买课程），`mock=false`。记录见 `live-index-status.json`。已完成扫描和首次索引初始化。

构建并按独立 JAR 快照启动，避免改写正在运行的 target JAR：

```bash
source scripts/dev-env.sh
mvn -o -pl kzai-course,kzai-learning,kzai-aigc,kzai-gateway -am package -DskipTests
bash scripts/run-services.sh restart course
bash scripts/run-services.sh restart learning
bash scripts/run-services.sh restart aigc
bash scripts/run-services.sh restart gateway
```

管理员通过 `GET /admin/ai/recommendations` 检查 namespace、mock 和各状态数量；`POST /retry` 重投 FAILED；`POST /rebuild` 重投当前命名空间并重置扫描游标。后两者完整路径为 `/admin/ai/recommendations/retry`、`/admin/ai/recommendations/rebuild`。首次启动自动初始化，无需导入测试课程或手动创建 ES mapping。

最终本地服务验收的正向请求用时 1.738 秒，返回 1002（39900 分）、1001（29900 分），课程详情复核一致；真实 qwen-plus 路由为 RECOMMEND，审计确认实际调用 `recommendCourses`，返回两张带推荐依据的卡片，整轮 10.609 秒。无匹配、零预算、模糊目标、跨用户访问及负预算验证均满足相应断言。临时会话与偏好已清理，真实隔离 ES 测试索引也已删除。

首次真实评测门槛为 0.6，无关农业目标也召回技术课程。调为 0.78 后，该无匹配场景返回空，两个固定正向场景均只返回相应课程。此门槛有小样本校准偏差：额外“从头写一个接收网页请求的服务器程序”未召回 Java 课，而数据清洗画图、分布式注册与网关、烘焙无匹配三个表达满足预期。换模型、增加课程领域或规模后应重新评估，当前结果不能外推为 100% 推荐准确率。

固定集中分别核对卡片真实 ID/名称/价格、购买资格、预算、已购排除、下架排除和不编造字段。诱导编造场景在此组验证的是服务事实边界，不能替代大规模 LLM 对抗测试。跨用户真实 API 和工具白名单另行验证。没有在现有业务库执行支付或确认购买；原购买确认与幂等由既有回归验证。

真实网络在本轮出现过 TLS 握手中断及对话上游超时，失败不计为质量通过。推荐查询明确降级，索引任务按状态重试；网络恢复不等于对所有运行环境作可用性保证。未执行生产压测、全目录人工相关性标注、付费交易到支付后的新开课验收，也未执行跨多实例真实数据库并发压测。视频时长字段不完整时无法保证学习周期适配；数据库里早期测试课程及不完整公开描述也会影响可推荐结果。

适用基础筛选依据公开适用人群文字规则（含“具备 Java 基础”等前置要求），没有将未结构化的人群描述当成完整能力模型；无法明确识别时提示进一步咨询。后续可在课程域增加标准基础标签并扩充人工标注集。

## 演示步骤

1. 登录学员账号，进入 AI 工作台，展开“按学习目标选课”；无会话时自动创建当前会话。
2. 输入“我已经会 Java 和 Spring Boot，想学习服务注册发现、网关和分布式事务”，其他条件可留空。查看真实卡片和依据；若都已购，按提示勾选包含已学课程查看真实状态。
3. 调低预算重新推荐，检查无合适课程时明确说明；清空预算后再次推荐。切换会话不串条件。
4. 输入领域外目标，检查不强行编造课程。索引/Embedding 不可用时检查关键词降级标识。
5. 对未购课程点“咨询课程”或“选择课程”，问题回填输入框；用户发送后咨询或展示购买确认，只有按既有门禁确认后才创建待支付订单。后续开课复用原有支付/学习权益流程。
