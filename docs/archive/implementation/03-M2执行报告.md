### 原表限制 → 最小增量方案

1. **`user.type` 无法区分管理员与普通员工**（原文仅 1员工/2学员/3老师）
   → 新增 `sys_user_role(id, user_id, role_code, create_time, creater)`，**`user` 表零改动**。
   兼容性：`sys_user_role` 无记录时按 `user.type` 推导角色（1→ADMIN，2→STUDENT，3→TEACHER），历史账号无需补数据。
2. **无操作日志载体**
   → 新增 `sys_operation_log(id, operator_id, operator_name, module, operation, target_type, target_id, detail, create_time)`。
3. **Token 撤销记录**
   → **未新增表**。沿用已落地的扩展设计 E1：Redis `AUTH:BLACKLIST:{jti}`（按 jti）+ `AUTH:TOKEN:VER:{userId}`（用户级版本号，支持批量失效）。
4. **姓名等字段**
   → 原始 `user` 表不具备，本阶段**未添加**；个人中心仅开放手机号编辑。

## 四、已实现的接口与页面

### 4.1 后端接口（均经网关 18080）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/auth/login` | 公开 | 返回 token + roles；携带 token 版本号 |
| POST | `/auth/logout` | 登录 | jti 进黑名单 |
| GET | `/users/me` | 登录 | 个人资料（不含密码）+ 角色 |
| PUT | `/users/me` | 登录 | 改手机号（身份取自 UserContext，不接受 userId 入参） |
| PUT | `/users/me/password` | 登录 | 校验旧密码 → BCrypt → 旧 token 全部失效 |
| GET | `/admin/users` | ADMIN/STAFF | 分页 + 账号/手机号/类型/角色/状态组合搜索 |
| GET | `/admin/users/{id}` | ADMIN/STAFF | 详情 |
| POST | `/admin/users` | ADMIN | 新增（账号/手机号唯一校验、角色白名单） |
| PUT | `/admin/users/{id}` | ADMIN | 编辑（仅手机号） |
| PUT | `/admin/users/{id}/roles` | ADMIN | 角色分配，同步 `user.type`，旧 token 失效 |
| PUT | `/admin/users/{id}/status` | ADMIN | 启停；禁用时旧 token 失效；禁止禁用自己 |
| PUT | `/admin/users/{id}/password` | ADMIN | 重置密码，旧 token 失效 |
| DELETE | `/admin/users/{id}` | ADMIN | 先校验关联（课程），通过后删账号与角色 |
| GET | `/internal/courses/count-by-creator/{userId}` | 内部 | 课程服务提供；网关拒绝外部访问 |

### 4.2 前端页面
- 登录页（M1，复用）
- 课程浏览 / 课程详情（M1，保留）
- **用户管理页**：组合查询、分页、新增/编辑弹窗、角色勾选、启停开关、重置密码弹窗、删除确认
- **个人中心页**：基本资料（账号/角色/权限/手机/状态/注册时间）、修改手机号、修改密码（含确认密码校验，成功后登出）
- **动态菜单与路由**：ADMIN/STAFF 显示「用户管理」，学员/教师不显示；直接访问 `/#/admin/users` 被拦截并提示「权限不足」后跳转课程页
- 登录失效：401 自动清 token 跳登录；403 弹出后端「权限不足」提示

关键断言（端到端）：
- 学员、教师访问 `/admin/users` → **403 权限不足**
- 伪造 `X-User-Roles: ADMIN` → **403**；伪造 `X-User-Id: 1` → 仍返回本人 `student01`

- 禁用后旧 token → **401 账号状态已变更**；禁用账号登录 → **403**

- 有关联课程（6 条）的用户删除 → 拒绝；无关联用户 → 删除成功
- 服务多次重启后数据仍在 MySQL（账号、角色、日志表均有数据）

## 七、仍然存在的问题

1. **JWT 密钥写在配置文件**（`kzai.jwt.secret`）：原文设计为配置注入，生产须改为环境变量/Nacos 加密配置。
2. **Nacos 未开启鉴权**：本地 standalone 默认关闭，部署前必须开启。
3. **token 版本号存 Redis**：Redis 清空后版本号归零，被失效的旧 token 会重新可用（极端情况下需依赖 token 自身有效期兜底）。
4. **前端包体积 1.1MB**：Element Plus 全量引入，后续可按需引入或做 manualChunks。
5. **spring-ai-alibaba-core:1.0.0-M6.1 POM 属性未解析**（`$com.google.protobuf`）打印两条 ERROR，依赖解析仍成功；M3 引入 DashScope SDK 若报 protobuf 缺失，显式声明 `protobuf-java` 版本即可。
