## 二、原始表一致性（重要约束）

**原始 12 张表零改动**，`course_chapter` 仍为 8 个字段，未新增任何字段。

本阶段新增 2 张表（迁移脚本 `sql/05_m3_course_manage.sql`，已执行）：

| 表 | 用途 | 关键设计 |
|---|---|---|
| `course_audit` | 审核记录（待审核/通过/驳回/强制下架） | `audit_status` 独立枚举，**不重定义** `course.status` 原文枚举（1待上架/2已上架/3下架/4已完结） |
| `course_resource` | 封面/教学资料/视频 | `kind` 1封面/2资料/3视频；章节视频用 `chapter_id` 关联，不给 `course_chapter` 加字段 |

字段语义补充：
- `course.price` 统一以**分**（INT）存储，免费课程 `price=0` 且 `free=1`；
- `course.section_num` 沿用原字段，章节增删后自动同步（未新增字段）；
- 课程分类保留 `first/second/third_cate_id` 三字段，本阶段**只开放两级创建**，三级字段不再写入。

## 三、关键实现约束（对齐需求"禁止假实现"）

1. **价格不使用浮点**：页面按「元」输入，服务层 `×100` 取整入库；返回同时提供 `price`（分）与 `priceYuan`。
2. **文件上传真实落盘**：文件写入服务端受控目录 `kzai.file.root`（默认 `data/upload`），库内只存相对路径；对外仅暴露 `/files/{id}/download` 受控地址，**不做假链接**。
3. **下载鉴权**：管理员 / 上传人 / 课程已上架且分类启用 才允许下载，其余 403；未登录 401。
4. **审核中禁止编辑**：`course_audit` 最新记录为待审核时，教师编辑返回 400，详情页返回 `editable=false`。
5. **状态机校验**：1→2（通过）、2→3（下架）、3→1（重新提交）之外一律拒绝；重复提交、重复下架被拒。
6. **章节逻辑删除**：`deleteById` 触发 `@TableLogic`，记录保留（`deleted=1`），列表过滤，`section_num` 同步。
7. **课程归属**：教师只能操作 `course.creater` 为自己的课程；管理员可代为处理。
8. **缓存一致性**：课程状态变更（编辑/提交/审核）时失效 `COURSE:{id}` 缓存，避免学员端看到过期数据。

端到端覆盖的关键闭环（脚本实测）：
1. 管理员建两级分类 → 排序修改落库 → 创建三级分类被拒（400）
2. 教师建课（价格 19900 分）→ 编辑 → 课程归属与内容落库
3. 教师 A 改教师 B 课程 → **403**，数据未被篡改；学员调用教师接口 → **403**
4. 章节新增 3 章 → 反序排序 → MySQL 校验 `chapter_order` → 删除第 3 章为**逻辑删除**（`deleted=1`），`section_num` 同步为 2
5. 上传 png 成功；`.exe` 被拒（400）；21MB 超限被拒（400）
6. 学员越权下载未上架课程资料 → **403**；未登录 → **401**；上架后学员下载 → **200**
7. 提交审核 → 重复提交被拒 → 学员访问未上架课程被拒（400）
8. 驳回（填原因）→ 课程保持待上架、学员不可见、教师可见驳回原因 → 重新提交 → 审核通过 → 学员可见
9. 强制下架（填原因）→ 学员不可见 → 重复下架被拒（状态流转校验）
10. 分类禁用 → 二级连带禁用 → 学员端分类树与课程列表均不含该分类 → 重新启用 → 删除被拒（"该分类下存在 N 门课程"）
11. 服务整体重启后课程/章节/审核数据仍存在，接口可查
