## 3. 学习服务架构与 OpenFeign 调用关系

```
浏览器 / kzai-frontend (5173)
        │  /api 代理
        ▼
kzai-gateway (18080)  ── JWT 校验 ── 注入 X-User-Id / X-User-Name / X-User-Roles
        │
        ├── /learning/** , /teacher/** ──► kzai-learning (18085)
        │                                        │
        │                                        ├─ Feign TradeClient ──► kzai-trade(18084)
        │                                        │     GET /internal/trade/entitlements
        │                                        │     GET /internal/trade/paid-courses
        │                                        ├─ Feign CourseClient ──► kzai-course(18083)
        │                                        │     GET /internal/courses/{id}
        │                                        │     GET /internal/courses/{id}/outline
        │                                        └─ Feign UserClient   ──► kzai-user(18081)
        │                                              （学情展示用户名）
        ├── /courses/** , /files/** , /teacher/courses/** ──► kzai-course (18083)
        ├── /orders/** ──► kzai-trade (18084)
        ├── /auth/** , /users/** , /admin/** ──► kzai-user (18081)
        └── /internal/** 一律拒绝外部访问（签名校验）
                     ▲
kzai-user 删除用户 ──┴── Feign LearningClient ──► kzai-learning
                          GET /internal/learning/lessons/count-by-user/{userId}
```

**身份与权限边界**

- 用户身份只取网关注入头，经 `UserContext` 读取；接口不接受请求参数中的 `userId`。
- 学习服务不直连 `order` / `course` 表，一律走 Feign 内部接口。
- `/internal/**` 需内部签名；网关对外直接拒绝。
- 任一依赖不可用：权益 fail-closed（视为无权益），删除关联校验返回负数按"存在关联"处理。

| 表 | 用途 | 归属 | 关键索引 |
|---|---|---|---|
| `learning_lesson_progress` | 章节级进度明细：状态、进度、视频断点、视频时长、累计有效学习时长、完成时间 | 一行 = 用户 × 课程 × 章节 | `uk_user_chapter(user_id,course_id,chapter_id)`、`idx_course`、`idx_user_course`、`idx_last_study` |
| `course_chapter_extra` | 章节扩展属性：试看标识、视频时长 | 一行 = 一个章节 | `uk_chapter(chapter_id)`、`idx_course` |

**原始 12 张核心表零改动**：`learning_lesson` 仍为原始 10 字段，仅由服务端写入 `status` / `progress` / `last_study_time` / `chapter_id`，字段类型、枚举与语义完全保留。

**并发与统计规则**

- 写入：`uk_user_chapter` 唯一索引兜底 + 「条件更新 → 回读」，避免并发双写。
- 有效时长：只按视频位置**真实前进量**累加（`delta = max(0, new - old)`），回放与重复上报不产生重复累计。
- 完成率：**已完成章节数 / 实际章节数**，服务端计算并回写 `learning_lesson.progress`；不信任前端百分比。
- 前端刷新/换设备：一律从服务端回读断点。

## 9. 四大业务闭环证据

### 场景 A：免费课程

```
学员登录 → 课程详情「免费加入学习」→ 跳转学习页 → 选章学习 → 保存进度 → 退出
→ 重新登录 → 继续学习（进度仍为 3/3）
```

- 浏览器：课程 `2112072304593248258` 入课后 `learning_lesson` 新增 1 行（id `2112072384125681666`，user 3）。
- HTTP：`免费课程加入学习成功 (200)`、`learning_lesson 真实落库 1 条 (1)`、`重复免费入课返回既有记录 (200)`。
- 未生成任何订单/支付记录（免费课不走 `order` 表）。

### 场景 B：付费课程

```
学员未购买 → 访问付费章节 403「未查询到该课程的已支付订单，请先购买课程」
→ 使用 SEED-DEMO 已支付订单（明确标注为演示数据，非真实支付、不计入成交额）
→ 受保护章节可访问 → 进度成功保存
```

- 已取消订单、已退款明细、已过期权益一律拒绝（M5 权益判定增强 + `EntitlementServiceTest` 12 用例）。
- 交易服务被 kill 后，学习相关请求返回受控错误（实测网关返回非 200，非 500 堆栈泄露）。

### 场景 C：学习完成与统计同步

```
学员完成多章 → 课程进度 33% → 66% → 100%
→ 教师学情统计同步（学习人数、完成率、章节完成分布、最近学习情况）
```

- MySQL 与接口逐字段比对一致：学习人数、已完成人数、累计有效学习时长、平均学习时长、章节完成分布。

### 场景 D：跨用户权限

- 学员 B 上报自己的进度后，学员 A 的断点与时长不变（实测 A=1200，B=999）。
- 学员 A 的「我的学习」列表只包含本人记录。
- 教师 A 查询教师 B 的课程学情 → 403「无权查看该课程的学情数据」。
- 学员访问 `/teacher/learning-stats` → 403「权限不足，无法访问该资源」。

## 10. 遗留问题与 M6（Spring AI 会话）建议

### 10.1 遗留问题

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | `CHAT_SESSION` / `INTERACTION` 删除关联 Guard 未接入 | 用户删除功能整体 fail-closed，一律拒绝 | M6（会话）接入 `ChatSessionAssociationGuard` 后再评估是否放行 |
| 2 | 课程问答数量、AI 采纳率返回 `null` | 学情统计不完整 | M10 问答数据建成后补齐，接口签名已预留 |
| 3 | 视频时长依赖教师/资源侧填写 | 未填时长时章节进度按位置比例无法计算 | 上传视频时解析真实时长或转码服务回填 |
| 4 | 学习服务不可用时的错误码为网关 500/000 | 用户体验一般，虽受控但文案不统一 | 网关增加熔断降级响应体，统一「服务暂时不可用，请稍后重试」 |
| 5 | 学习时长仅按视频播放位置前进量统计 | 图文章节、练习场景的有效时长尚未覆盖 | 后续扩展「章节停留时长上报」口径并登记 |
| 6 | 未做真实支付 | 付费闭环仍依赖 SEED-DEMO | 支付阶段接入后需保留演示数据标注与审计区分 |

### 10.2 M6（Spring AI 会话开发）建议

1. **会话服务独立成 `kzai-ai`/`kzai-chat`**，沿用本阶段的 Controller → Service → Mapper 分层、统一 `R<T>` 与 `requestId`、网关注入身份。
2. **会话必须绑定真实学习上下文**：`courseId` / `chapterId` 需复用本阶段 `GET /learning/courses/{id}/access` 的权益结论，未取得权益的学员不得就该课程发起付费问答。
3. **会话记录落库后同步注册删除 Guard**（`CHAT_SESSION`），补齐 `REQUIRED_DELETION_BINDINGS`，解除删除功能 fail-closed。
4. **AI 采纳率口径先行定义**：建议在会话表设计时就预留 `adopted` 字段与采纳事件时间，避免 M10 再回溯。
5. **敏感与成本边界**：会话接口需限流与审计，AI 输出不得直接作为课程事实（评分、价格、权益）来源。
6. **复用本阶段的 CSV 安全工具**（`CsvUtils`）与 Long 字符串序列化约定，避免 ID 精度与注入问题重复出现。
