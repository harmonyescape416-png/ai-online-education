## 1. M7 实际验收及遗留问题修复结果

### 1.1 Spring AI proxyToolCalls 运行级验证（任务书 A-1/A-2）

**字节码核验**（javap 反编译 spring-ai-alibaba-core 1.0.0-M6.1 `DashScopeChatModel` 与 spring-ai-core 1.0.0-M6 `AbstractToolCallSupport`）：

```java
// call() 与 stream() 均为同一门控：
if (!isProxyToolCalls(prompt, defaultOptions) && isToolCall(resp, Set.of("TOOL_CALLS", "STOP"))) {
    List<Message> results = handleToolCalls(prompt, resp);        // 框架执行工具
    return call(new Prompt(results, prompt.getOptions()));        // 结果回传模型续轮
}
return resp;   // isProxyToolCalls=TRUE → 跳过执行，直接返回 ToolCall 元数据
// isProxyToolCalls：运行时 options 值优先；两者皆未设置 → 默认 FALSE（执行）
// schema 发送与执行解析都来自构造期 register=merge(defaultOptions, toolFunctionCallbacks)
// 运行期 options 的回调仅提供名字；resolveFunctionCallbacks 只查 register/resolver
```

**逐项回答任务书问题**：

| 问题 | 结论（字节码 + 运行级测试） |
|---|---|
| proxyToolCalls=true 时工具由谁执行 | **无人执行**——模型把 ToolCall 元数据直接返回给调用方（M7 缺陷①） |
| 模型返回 ToolCall 后是否真正调用 CourseTools/OrderTools | `handleToolCalls→executeFunctions` 按**构造期 register** 解析回调执行；M7 未注册 → `IllegalStateException: No function callback found`（M7 缺陷②）。修复后由 register 解析执行 |
| 工具结果是否传回模型 | 以 `ToolResponseMessage`（与 ToolCall id 对应）拼入第二轮 Prompt，运行级测试断言通过 |
| 模型是否继续生成最终文本 | 是——第二轮调用返回 STOP 文本，测试断言"根据查询结果，为您找到 Java 基础课程" |
| 是否存在只返回 ToolCall 元数据的情况 | **存在**（proxyToolCalls=TRUE），已实证并修复 |
| 流式是否重复调用/无限循环 | 流式同一门控、同语义；**框架递归无最大迭代保护**（M6 局限）→ 工程兜底为工具轮次预算（每工具每轮 8 次，超限返回受控提示），预算语义有单测 |

**运行级测试**：`ProxyToolCallsRuntimeTest`（6 用例）——脚本化计数模型走**真实框架代码**（isToolCall/executeFunctions/buildToolCallConversation），验证：proxy 缺省时工具执行 1 次、模型调用 2 次、ToolResponseMessage 回传、最终文本生成、ToolContext 到达回调、流式同语义；并固化两个缺陷的失败路径防止回归。

**修复内容**：
1. `DashScopeChatProvider.streamWithTools`：`proxyToolCalls(TRUE)` → `FALSE`（显式）。
2. `AiModelConfig`：2 参构造 → 5 参构造，把 `ToolRegistry.callbacks()` 注册进模型 register；白名单仍由运行期子集控制。

## 4. 路由规则、失败兜底与会话去重

- **路由先于专业 Agent**、非流式、严格枚举（RECOMMEND/CONSULT/BUY/KNOWLEDGE/OTHER）。
- **OTHER（寒暄/无关）直接回复**（无工具、不进专业 Agent，终态 agent=OTHER）。
- **无法解析/超时/异常 → 兜底 CONSULT**（fallback=true，errorKind=UNPARSEABLE/TIMEOUT/ROUTE_ERROR），不阻塞用户。
- **路由零落库**（RecordOptimization 等价，D8-5）：路由用进程内临时消息，不写 Redis；e2e 实证 5 轮对话 Redis 恰好 5 user + 5 assistant、会话详情恰好 10 条可见消息。
- **多轮切换上下文连续**：专业 Agent 输入 = 自身 Prompt 快照 + Redis 完整历史；B14 由 M6 历史加载与 M8 e2e 共同覆盖。
- **路由状态按 userId+sessionId 隔离**：提案确认状态即路由上下文的一部分，e2e B 访问 A 会话 403。

## 5. Agent 工具权限矩阵（运行期最小授权）

| Agent | searchCourses | getCourseDetail | createPreOrder | 说明 |
|---|---|---|---|---|
| ROUTE | ✗ | ✗ | ✗ | 无任何业务工具；模型构造期 register 也不含其独立工具 |
| RECOMMEND | ✓ | ✓ | ✗ | 只读推荐 |
| CONSULT | ✓ | ✓ | ✗ | 只读咨询；已购/学习问题引导至我的课程/订单 |
| BUY | ✓ | ✓ | ✓ | 预下单受确认门禁（PurchaseProposalStore）+ 稳定 requestId + 交易侧幂等三重保护 |
