### 2.2 FAILED 事件的安全重试方式（本轮不建运维后台，明确手册）

- FAILED 行保留 `error`（≤480 字）与 `request_id`，Worker 候选查询（`status=0 AND next_retry<=now OR status=1 AND lease<now`）**天然不触碰**（IT 实证）。
- 安全重试动作（DBA/运维手册）：
  ```sql
  UPDATE sys_event_outbox SET status=0, attempt=0, next_retry_time=NOW(), error=NULL
  WHERE id=? AND status=3;   -- 复位后 Worker 自动重新投递（IT 第 7 项实证）
  ```
- 排查入口：`SELECT * FROM sys_event_outbox WHERE status=3`，结合 `error/request_id` 定位 user 服务日志。

## 3. M9 版本检索及 TopK 核查结果（任务书第一部分 2）

### 3.1 现有实现核对结论

`KnowledgeRetriever.retrieve` 原实现已有**有界候选集扩大**（`knnSearch(vector, topK*3, filter)`，k=18、num_candidates=90）+ MySQL 逐条复核（已发布/未删除/**版本一致**/INTERNAL/PROTECTED 权益 fail-closed），直到取满 topK。**「ES 返回 TopK6 后才过滤」的担心不完全成立，但挤占窗口真实存在**：候选窗口内无效版本切片会挤占有效结果的候选位。

### 3.2 挤占风险实证（真实 ES，多版本混合数据）

构造：文档 E 已发布 V1（6 片）+ **未发布 V2 残留 20 片**（模拟重建中途崩溃，大于 18 窗口）+ 文档 F 已发布 6 片。对照证据（`KnowledgeEsIT` 第 8 用例日志）：

```
[M12-IT] 无版本预过滤时 k=18 窗口中未发布 V2 切片数 = 12 / 18（挤占风险证据）
```

即 18 个候选位中 **12 个被无效版本占据**——有效文档可能被挤出窗口造成**漏召回**（这与「无关问题检索为空」是不同性质的问题：前者是有效版本被挤占，后者是语义相关性不足/无证据）。

### 3.3 修复：权威版本白名单预过滤（D12-10）

- `KnowledgeRetriever` 检索前从 MySQL 加载**已发布未删除**文档的 `(docId, index_version)` 权威白名单，作为 kNN filter 的 `bool.should` 子句（`minimum_should_match=1`）——未发布/过期版本切片**不进入候选窗口**；
- MySQL 逐条复核保留（删除/撤回/权益实时权威，双保险）；白名单 >500 文档回退旧口径（防超大查询）；MySQL 异常时回退并告警（不放大权限）；
- 命中结果新增 `indexVersion` 字段返回（评测与审计依据）。

### 3.4 修复后验证（真实 ES）

- E 的 20 片未发布切片 0 出现；E 检索仅返回已发布 V1；
- **F 始终可检索**（不被 E 的无效版本挤出）；「只重建 A，B 始终可检索」「V2 未发布不召回、发布后仅召回生效版本」「延迟清理不删当前发布版本」（原 7 用例，含故障注入）全部保持通过：**`KnowledgeEsIT` 8/8**。

## 4. 数据库扩展结构与批准记录（任务书第三部分）

- **批准方式**：提交最小 DDL 设计（字段/索引/状态机/并发/历史）后经用户四项确认批准：①三张表方案 ②重启策略=明确终止 ③BUY 工具=Dry-run 记录 ④评测身份=默认学员视角+admin_test_access。
- 迁移：`sql/13_m12_evaluation.sql`（幂等，不覆盖历史编号；执行后核验三表存在、索引生效）。

| 表 | 说明 | 关键设计 |
|---|---|---|
| `ai_eval_run` | 评测批次 | `active_flag` 生成列（仅运行中=1）+ `UNIQUE` → **全局至多一个运行中批次**（防重复点击，DuplicateKey→受控 400）；快照 `provider/model_code/embedding_provider/kb_physical_index/prompt_snapshot/case_ids/executor_id`；状态机 0运行中→1成功/2失败/3部分成功/4已终止/5不可执行(REAL未配置,创建即终态) |
| `ai_eval_result` | 单条结果 | `UNIQUE(run_id,case_id,attempt)` → **重试=新 attempt 新行**，历史永不覆盖；status 0待执行/1完成/2执行失败/3超时/4跳过（**执行失败与模型判断错误天然分离**）；token 三列 + `token_source`（provider/unavailable/mock_na）；`refusal/refusal_rule/has_citation/leak_suspected/write_tool_attempt/passed/verdict_rule/fail_reason` |
| `ai_eval_case_meta` | 标注扩展 1:1 | `should_refuse/needs_citation/expect_tool/refuse_reason/note(标注理由)/data_deps(真实数据依赖)/source(标注来源)/is_regression` |
| `ai_eval_case`（原始） | **11 字段零改动** | `actual_*/latency_ms/token_usage/passed` 仅回写「最近一次执行」镜像；历史事实以 `ai_eval_result` 为准 |

**为什么需要 `ai_eval_case_meta`（不能复用现有字段）**：`expected_doc_id` 语义=期望召回文档/课程、`expected_intent` 语义=期望意图、`question` 是被评测输入本身——均无法承载「是否应拒答/需引用/标注理由/数据依赖」；在原始表加列违反「不允许修改结构」红线。

**为什么需要 `ai_eval_run`/`ai_eval_result`**：一个用例可执行多次，每次对应不同模型/Prompt/知识库版本与实际结果；只覆盖 `ai_eval_case.actual_*` 会丢失历史评测记录（任务书第三部分明确指出）。

- 标注 SEED：`sql/13a_m12_eval_seed.sql`（由 `scripts/e2e-m12-setup.sh` 以真实 docId 生成并执行；文件头注明「人工标注种子，不是模型评测结果」）。**SEED 只提供用例标注，绝不作为评测结论**。
