## 6–7. 会话监管与问答监管实现

**AI 会话监管**（`/admin/supervision/sessions/**` → aigc，@RequireRoles(ADMIN)）：
- 分页查询：用户/时间区间 SQL 级过滤；**关键词/意图为 Redis 消息级过滤**（限定 300 条扫描窗口防全库扫描，超窗提示缩小条件）；assistant 消息自 M13 起携带 `agent` 元数据（旧消息如实显示「未知」，不伪造）；
- 详情：元数据 + 消息（**Redis TTL 过期 → 明确显示「消息内容已过期或不可用」**）+ 工具卡片（COURSE_CARD/ORDER_CARD）+ RAG 卡片 + provider 标识 + token（若已记录）；TOOL_AUDIT 为结构化日志（非持久化），页面不宣称可查询的工具审计持久化能力；
- 复核：标记（原因必填）→ 处理（仅待复核行可处理，条件更新防并发重复处理）→ 历史完整（只插入不覆盖）；
- 红线：监管只读 Redis 消息，**绝不修改用户原始会话消息**；复核落 `sys_session_review`（SESSION_MARK=9、处理记录真实持久化）。

**课程问答监管**（`/admin/supervision/questions/**` → learning，ADMIN 跨课程；TEACHER 仍限本人课程走原接口；STUDENT 403）：
- 查询全部问答（课程/用户/时间/关键词/隐藏筛选）；详情展示 AI/教师/学员来源、MOCK/REAL 模型标识（modelCode）、修正历史（prev_content/corrector/correctTime）、隐藏与精华状态；
- 隐藏/恢复复用 `TeacherQuestionService` 既有方法（ADMIN 豁免归属校验，**不绕过权限直改核心表**）；`interaction_question.status` 保持原始语义 0未查看/1已查看（断言 B5 实证）；
- 监管原因必填，真实写入 `sys_operation_log`（ADMIN_HIDE_QUESTION/ADMIN_SHOW_QUESTION 等）。
