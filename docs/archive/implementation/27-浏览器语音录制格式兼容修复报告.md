# 27-浏览器语音录制格式兼容修复报告（M15.11-R2）

> 执行依据：用户《浏览器语音输入故障修复指令》（本轮不授权真实付费 STT；先本地格式兼容与 MOCK 回归）。
> **故障闭环**：定位并修复「无法识别的文件头」字节级根因 +「语音能力加载中」状态机缺陷 + 前端录音格式统一（WebAudio WAV 主路径）。

## 1. 根因定位（三项，全部代码级实证）

| # | 故障现象 | 根因 | 定位 |
|---|---|---|---|
| 1 | 「无法识别的文件头（非已知音频格式）」 | AudioValidator.detectMagic 的 webm 魔数检查存在有符号 byte 比较缺陷：`d[2] == 0xDF`（Java byte 0xDF=-33，与 int 223 永不相等）、`d[3] == 0xA3` 同理——Chrome MediaRecorder 的 audio/webm;codecs=opus 录音（EBML 头 1A 45 DF A3）永远无法命中 webm 识别分支 → detectMagic 返回 null → 报该错 | AudioValidator.java webm 分支 |
| 2 | 「语音能力加载中」持续显示 | REAL 模式下 /audio/capabilities 成功返回（enabled=true），但前端 voiceNotice 仅在 mock 时设置，模板 `{{ voiceNotice || "语音能力加载中" }}` 回退常显「加载中」——加载中/可用/不可用/失败四态未区分 | AiWorkbenchView.vue loadVoiceCapabilities |
| 3 | 潜在格式不匹配类故障 | 前端上传文件名映射默认回退 mp4（blob.type 非标准时扩展名与真实容器可能不一致）；MediaRecorder 容器（webm/opus）对 qwen3-asr 的支持存在不确定性 | AiWorkbenchView.vue stopRecord 上传段 |

## 2. 修复内容

### 2.1 后端 AudioValidator.java
1. webm 魔数修复：`(d[2] & 0xFF) == 0xDF` 无符号比较（注释说明原缺陷）——Chrome webm 录音可正确识别
2. 合法容器以真实格式为准：魔数可识别的音频不再因扩展名与容器不一致被 FORGED_EXT 拒绝（MediaRecorder Blob type 缺失/浏览器默认容器差异的真实场景；防伪造仍由魔数校验承担——文本/EXE 无法伪装音频文件头）
3. detectMagic null 的错误信息携带前 16 字节 hex 诊断头（head=...，不含业务内容）
4. 保持不变：5MB 上限、空文件拒绝、魔数白名单（wav/mp3/ogg/webm/m4a-mp4/flac/aac/ADTS）、并发与时长限制

### 2.2 前端 speech.js（重写录音路径）
- 主路径 WavRecorder：getUserMedia → AudioContext(16kHz) → ScriptProcessor 采集 Float32 PCM → Int16 → 44 字节 WAV 头封装 → Blob('audio/wav')——统一输出 WAV（qwen3-asr-flash 最稳输入；从根上消除容器/扩展名/魔数匹配问题）；时长上限按采样数硬切（达限自动停止）；资源全量释放（tracks/processor/context.close）
- 降级路径 MediaRecorderFallback：不支持 WebAudio 采集的浏览器使用 MediaRecorder，上传文件名按实际 mime 精确映射（webm/ogg/mp4——不伪装成 wav）
- 保留：权限拒绝/无设备/HTTPS 环境友好提示、时长 tick、取消语义、TTS 播放单例管理

### 2.3 前端 AiWorkbenchView.vue
1. startRecord：WavRecorder 主路径 + MediaRecorderFallback 降级（window.AudioContext 探测）
2. 上传扩展名按实际 blob.type 精确映射（wav/webm/ogg/mp4/mp3）
3. capabilities 四态状态机：加载中（初始）→ 可用（REAL：显示「语音就绪…」）/ 不可用（enabled=false：显示「语音功能已关闭」）/ 请求失败（显示「状态获取失败」）——消除常显「语音能力加载中」
