## 1. 原始安全问题与根因

QuestionService.validateAndAuthorize（learning）经 courseClient.learnOutline(courseId) 校验课程存在性——但 course 侧 outline 对下架课程仍返回数据（仅 deleted=1 才返回 null），且 learning 侧未检查返回的 status 字段 → 下架课程 API 直提 code=200（M15.12 报告披露）。

## 2. 后端修复（最小增量）

kzai-learning/.../service/QuestionService.java（唯一修复点，+8 行）：

在 learnOutline 空判后新增：status≠2 / categoryEnabled=false / studentVisible=false 任一即抛「课程不存在或已下架」。

- 复用既有内部课程快照接口（/internal/courses/{id}/learn-outline），零新增接口、零表变更
- 一个条件覆盖三种不可见：下架（status≠2）、禁用分类（categoryEnabled，course 侧已含两级分类 AND 判定）、学员不可见
- fail-closed：课程服务异常维持既有「课程服务暂不可用」
- 课程级提问不新增购买权益要求（权益校验仅在章节关联提问，规则不变）

## 3. 课程状态、分类、权限判断（最终语义）

| 判定 | 数据源 | 拒绝行为 |
