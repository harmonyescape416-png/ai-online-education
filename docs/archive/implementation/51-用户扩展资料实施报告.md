## 1. 数据模型（批准方案 A 落地）

| 项 | 实现 |
|---|---|
| 新表 | user_profile_ext（user_id PK 1:1 共键 / nickname VARCHAR(30) / avatar_url VARCHAR(500) / create_time / update_time）——**12 核心表零改动** |

## 2. 后端接口扩展（user 服务）

| 接口 | 行为 |
|---|---|
| PUT /users/me | 扩展：nickname（@Size max 30）/avatarUrl 保存到扩展表（saveExt upsert，null 字段不覆盖） |
| GET /users/me | 扩展：合并扩展表回读（nickname/avatarUrl 填充 UserVO） |
| POST /users/me/avatar（新增） | MultipartFile 上传：类型白名单 jpg/png/webp、≤2MB、服务端按 userId 命名、路径 normalize+startsWith 防穿越、旧格式清理、upsert 扩展表 |
| GET /users/me/avatar/file/{fileName}（新增） | 头像访问：文件名正则白名单+路径防穿越+按扩展名 Content-Type；**网关白名单放行**（公开资源，头像非机密） |

## 3. 前端 ProfileView

- 头像：预览（avatarUrl 或首字母占位）+ 上传按钮（file input，jpg/png/webp ≤2MB 校验）+ 上传后 fetchProfile 回读
- 昵称：输入框（maxlength 30）+ 保存提交 nickname
- 回读：fetchProfile 后 fillExt()（表单与显示同步）

## 4. E2E 实测（HTTP，student01）

| 场景 | 结果 |
|---|---|
| PUT nickname=小栈同学 → 回读 | DB 与接口均返回「小栈同学」 |
| 上传 1px png → avatarUrl | /users/me/avatar/file/3.png |
| 头像公开访问（新 gateway 白名单） | HTTP 200 image/png |
| **完整链路**：PUT → 查 DB → 上传 → 查 DB → GET 回读 | **nickname 与 avatarUrl 全保留**（upsert 不互相覆盖） |
| 越权/路径穿越 | filename 伪造被服务端命名覆盖；路径 normalize+startsWith 防护 |

## 5. 修复过程披露
