# 52-头像上传与昵称保存修复报告（M15.15 补充）

> 执行依据：用户《上传头像和修改昵称后保存不成功，且前端页面无法显示更新后的信息》排查修复指令。
> **结果：两个根因修复并前端全链路实测通过（昵称持久化+回读、头像上传落盘+预览显示）。完成后暂停等待验收。**

## 1. 问题①：头像上传保存失败——根因与修复

**根因（复现确凿）**：前端 onAvatarChange **手动设置** Content-Type: multipart/form-data（无 boundary）——axios 对 FormData 本应自动生成含 boundary 的头，手动覆盖后**后端 MultipartFile 解析失败**。

复现对照（agent-browser fetch 实测）：手动 CT → **500**；自动 CT（不设头）→ **200**。

**修复**：移除手动 headers（axios 自动生成）——一行修复。

实测（前端真实链路）：注入 File → change 事件 → 上传 → **服务端 data/avatar/3.png 更新（时间戳+70 字节 1px png）** + 后端 avatarUrl 保留。

## 2. 问题②：昵称保存失败——核验与修复

核验：saveProfile 提交体/后端逻辑正确（curl 实测 PUT 成功）——**前端缺陷**：**无 catch**（接口失败时 Unhandled rejection + 用户无失败提示，观感=「保存不成功」）。

修复：补 **catch**（失败 ElMessage.error + **保留用户输入**）。

实测：输入「修复验证昵称」→ 保存 → 提示「资料已更新」→ **后端 nickname=修复验证昵称**（持久化）→ **输入框回读**。

## 3. 问题③：保存后页面未显示最新——根因与修复

根因：同①——头像上传失败后 avatarUrl 未更新；昵称因②失败未回填。修复①②后：
- 头像：上传成功 → avatarPreview 本地预览立即显示 + fetchProfile 回读 avatarUrl（img src 走网关公开 GET 200）
- 昵称：保存成功 → fetchProfile → **fillExt() 回填输入框**（M15.14-R6 已挂载）

实测：昵称输入框值=修复验证昵称（保存后回读）；头像 blob 预览显示。
