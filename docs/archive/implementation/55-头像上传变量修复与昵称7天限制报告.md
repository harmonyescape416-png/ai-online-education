# 55-头像上传变量修复与昵称7天限制报告（M15.15 补充③）

> 执行依据：用户《修复 Can't find variable: request + 昵称 7 天一次修改限制》指令。完成后暂停等待验收。

## 1. 问题①：Can't find variable: request（已修复）

**根因**：M15.14-R6 引入 onAvatarChange 时使用了 request.post 但 **ProfileView 未导入 request**（该文件此前只用 profileApi 封装）→ 点击上传 → ReferenceError → 上传中断。

**修复**：api/index.js 的 profileApi 新增 uploadAvatar: (formData) => request.post('/users/me/avatar', formData)——ProfileView 改走 profileApi.uploadAvatar(fd)（API 封装统一，request 仅在 api 层使用）。

实测（agent-browser 注入 File → change）：**头像已更新提示** + **顶栏头像同步** + **控制台 Can't find variable = 0**。

## 2. 问题②：昵称 7 天一次修改限制（服务端权威校验，已修复）

| 层 | 实现 |
|---|---|
| 数据模型 | user_profile_ext 新列 nickname_updated_at（NULL=从未修改）——deploy/migrations + classpath DDL 同步；initializer ALTER 补列兜底（存量表幂等） |
| 服务端校验 | ProfileService.updateProfile：本次提交昵称且与现有值不同时——ext.nicknameUpdatedAt 距今 <7 天 → **400「昵称 7 天内仅可修改一次，还需 N 天后才能再次修改」**；成功修改 → 记录时间戳 |
| 边界规则 | 首次设置（NULL）不受限；**昵称未变化不触发限制也不刷新时间戳**；头像上传不受限 |
| 前端 | **不展示「7 天内可修改一次」文案**（按指令）；失败时显示服务端返回的具体消息（含剩余天数） |

实测：第 1 次改「七天限制验证」→ 200；**第 2 次 → 400「还需 7 天后才能再次修改」**。
