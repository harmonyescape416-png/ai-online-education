# 62-账号体系设计方案（用户注册 + 管理员添加并存）——只读方案，待批准

> 依据：用户《设计账号体系：用户注册与管理员添加并存》指令——**先不改代码**。
> 现状核查结论：user 表已有 uk_username/uk_cell_phone 唯一索引；管理端单条添加接口已有（AdminUserController POST）；**注册页与批量导入不存在**（需新增）；**user 表零结构变更可实现**（来源标识复用 creater 语义）。

## 一、两条创建路径定义

| 维度 | A. 用户自主注册 | B. 管理员单条添加 | C. 管理员批量导入 |
|---|---|---|---|
| 入口 | 登录页「注册账号」链接 → /register | 管理端-用户管理「添加账号」 | 管理端-用户管理「批量导入」CSV |
| 接口 | POST /auth/register（公开，网关白名单） | POST /admin/users（已有，@RequireRoles(ADMIN)） | POST /admin/users/import（新增，ADMIN） |
| 创建方式 | 用户自助表单 | 管理员单条表单 | CSV 文件解析（≤500 行/批） |
| 创建角色限制 | **仅学员**（type=2，固定） | 学员(2)/教师(3)（**管理员(1)不可后台直授**，防越权提权） | 仅学员/教师 |

## 二、账号来源标识（user 表零变更）

**复用 creater 字段语义**（原始设计即「创建人」）：

| 来源 | creater 值 | 含义 |
|---|---|---|
| 用户自主注册 | **0** | 系统自助（约定 0=本人注册） |
| 管理员添加/导入 | **管理员 userId** | 后台创建（现状语义不变） |

- 查询口径：creater=0 → 注册账号；creater>0 → 后台创建；**用户管理列表增加「来源」列**（注册/后台）
- updater 维持现状语义（最后修改人）
- **不新增 source 列、不改 12 核心表结构**

## 三、默认角色与权限分配

| 路径 | type | roles（派生） | 权限说明 |
|---|---|---|---|
| 注册 | 2 固定 | ['STUDENT'] | 仅学员端功能——**注册表单不提供角色选择** |
| 管理员添加 | 2 或 3（下拉） | STUDENT/TEACHER | 教师需管理员指定；**type=1（管理员）不可后台直授**（防越权提权） |
| 批量导入 | CSV 列指定（2/3） | 对应派生 | 行级校验，非法 type 该行失败 |

## 四、审核与激活流程

| 路径 | 初始状态 | 流程 |
|---|---|---|
| 注册 | **status=1 直接激活**（M1 简化，密码用户自设 BCrypt） | 注册即登录；**预留审核扩展**：后续如需人工审核，初始 status 置 0（禁用语义复用）+ 管理端「待审核」筛选，无需表变更 |
| 管理员添加 | status=1 直接激活 | 初始密码管理员设置（明文或「随机生成」展示一次）；建议首登改密（后续增强） |
| 批量导入 | status=1（CSV 可选 status 列） | 初始密码 CSV 指定或统一初始密码 Init@123456（导入结果披露，建议首登改密） |

## 五、数据校验规则（三路径统一，服务端权威）

| 字段 | 规则 | 校验位置 |
|---|---|---|
| username | **唯一**（uk_username 索引兜底 + 服务层 existsUsername 前置）；3-20 位字母/数字/下划线 | 注册/添加/导入逐行 |
| cell_phone | **唯一**（uk_cell_phone + existsPhone）；格式 ^1[3-9]\d{9}$；可空 | 同上 |
| password | 6-32 位（与修改密码规则一致）；BCrypt 存储 | 同上 |
| type | 枚举 2/3（1 禁止创建） | 同上 |
| 批量导入 | 行级错误收集（行号+原因），**合法行照常导入、错误行返回清单**（不整批失败）；文件内与库内重复 username/phone 去重校验 | 导入专用 |

**唯一性并发安全**：前置 exists 校验 + **唯一索引兜底**（DuplicateKeyException 统一转「用户名/手机号已被占用」）。

## 六、统一管理与互不冲突保证

1. **同一 user 表**：两条路径写同一表、同一字段集——无并行账号体系
2. **权限统一派生**：roles 由 type 经 userRoleService.resolve 派生（现状不变）
3. **管理端全生命周期**：注册账号在用户管理列表**可见可管**（禁用/启用/重置密码/升教师/删除）——与后台创建账号无差别
4. **审计闭环**：注册（自助）、添加（操作日志 OP_CREATE）、导入（操作日志+批次摘要）全部留痕
5. **邮箱说明**：user 表无 email 列——**M1 不引入邮箱**（避免表变更）；如需邮箱复用 user_profile_ext 扩展表模式（另行批准）
