# 64-修改手机号短信验证码确认流程报告（M15.18）

> 执行依据：用户《修改手机号增加短信验证码确认流程》指令。**完成后暂停等待验收。**

## 1. 流程设计

```
个人中心-手机号 → 输入新手机号 → [获取验证码]（scene=CHANGE_PHONE，登录态）
  ├─ 新号已绑定任意用户（学员/教师/管理员）→ 400「该号码已注册」不发码
  ├─ 60s 限流/日限/IP 限（复用既有机制）
  └─ 发送成功 → 验证码输入 → [确认更换] POST /auth/change-phone
       ├─ 验证码一次性消费（Lua，绑定 CHANGE_PHONE+新号）
       ├─ 占用检查（findByPhone →「该号码已注册」）+ 唯一索引兜底
       └─ user 服务更新 cellPhone（操作日志「修改手机号（短信验证通过）」）
```

## 2. 接口

| 接口 | 变更 |
|---|---|
| POST /auth/sms/send | scene 扩展 **CHANGE_PHONE**（登录态强制——auth.requireLoginUserId 解析 JWT subject）；发送前占用检查 |
| **POST /auth/change-phone**（新增） | 登录态+验证码消费+占用拒绝+Feign user 更新 |
| POST /internal/users/update-phone（user 新增） | 格式校验+唯一前置+唯一索引兜底+操作日志 |
| ProfileService.updatePhone（user 新增） | 各角色一致；幂等（同号返回）；DuplicateKey→「该号码已注册」 |

## 3. 修复过程披露

1. **scene 枚举未扩展**：CHANGE_PHONE 被拒「不支持的验证码场景」——requireValidScene 扩展（KEYS 按 scene 隔离，REGISTER/CHANGE_PHONE 码互不混用）
2. **JWT claim 取值**：userId 在 **subject**（非 uid claim）——requireLoginUserId 修正
3. **占用测试用例修正**：首次用 13800138000（student01 已改走=未占用）误判——改用当前占用号复验通过
