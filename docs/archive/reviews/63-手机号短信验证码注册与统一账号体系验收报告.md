## 2. 注册流程（POST /auth/register，公开）

手机号格式校验 → 密码规则（6-32）→ 确认密码 → **验证码一次性原子消费（Lua）** → 手机号唯一（前置+索引兜底）→ username 生成（u_+SecureRandom 12-16 位，唯一重试 5 次）→ BCrypt → **type=2 固定/creater=0/status=1**（请求不可指定角色/ID/创建人）→ 一次性消费已完成。

实测：注册成功 {"username":"u_tj5h594ew0j9","message":"注册成功，请使用手机号和密码登录"}；**重复消费** → 「验证码已过期或未发送」。

## 3. SMS 接口与验证码存储

- **POST /auth/sms/send**（公开+网关白名单）：格式/场景枚举/**已注册拒绝**（引导直接登录）/限流 → 响应仅 {sent,message,ttlSeconds}——**不返回码值明文**
- **存储**：HMAC-SHA256(phone+code, pepper) 摘要——非明文、不可反推；绑定 phone+scene（场景不混用）；新码覆盖旧码（旧码失效）

## 4. Redis 限流与一次性消费

| 机制 | 实现（全部 Redis 原子 TTL） |
|---|---|
| 发送间隔 60s | SETNX interval key |
| 日限 10 次/手机号 | INCR+25h TTL |
| IP 限 20 次/小时 | INCR+1h TTL |
| 失败 5 次作废 | INCR failKey+码删除 |
| **一次性消费** | **Lua 脚本**（校验+DEL 同脚本——并发无 GET+DELETE 窗口） |

实测：60s 重复 → 400「发送过于频繁」；错码 → 「验证码错误」；消费后重复 → 「已过期或未发送」。

## 5. MOCK/REAL 隔离

- **SmsService 接口**：MockSmsService（@ConditionalOnProperty mock）/RealSmsService（real）——**ObjectProvider 按 mode 选择**（修复 Bean 缺失启动失败）；不混合
- **MOCK**：不调平台零费用；测试夹具通道（SMS:MOCKFIX 键，仅 mock 模式+夹具密钥匹配）——码值不落日志（掩码手机号）
- **REAL 结构就绪**：AccessKey/签名/模板外部注入（kzai.sms.real.*）——未配置 → isConfigured=false → 503 安全拒绝

## 9-10. 管理员单条添加 + CSV 批量导入

- **单条**：随机初始密码（**废除公开 DEFAULT_PASSWORD**）+ **initialPassword 一次性返回**；**禁 ADMIN**（type=1/roleCodes ADMIN 均 400）
- **CSV 导入**（POST /admin/users/import）：≤500 行/512KB、UTF-8 BOM 剥离、行级校验（格式/唯一/文件内重复/角色白名单禁 ADMIN）、**部分成功**（实测 3 成功 1 失败「手机号格式不正确」）、随机密码一次性返回、操作审计
- **激活策略**（输出待批）：导入手机号≠已验证——当前首登用初始密码；「验证码首登激活」需持久化激活状态（另行批准）
