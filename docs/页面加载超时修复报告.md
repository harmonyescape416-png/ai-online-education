# 四个管理与教师页面加载超时修复

验证日期：2026-10-23。本次直接检查本机运行服务、数据库连接、HTTP 接口及浏览器页面。

## 故障定位

受影响页面：管理员运营看板、课程问答监管，教师学情统计、问答管理。

共同依赖是 `kzai-learning`：后三个页面直接读取它，看板由 `kzai-user` 聚合其统计。
故障时端口 18085 和 Nacos 均显示实例在线，但直连 `127.0.0.1:18085` 或注册地址，
连无登录的请求也不能及时返回。五个页面接口并发探测在 7 秒上限内均未返回；
user 历史日志持续记录 `Read timed out ... /internal/learning/stats/questions`。

MySQL 当时没有正在执行的长查询，相关连接处于 Sleep。两份 JVM 线程快照没有发现
业务方法中的长时间 SQL 或锁等待。因此本次故障不是四个独立页面的慢查询问题。

运行进程 94683 的打开文件指向 `target/kzai-learning-1.0.0-SNAPSHOT.jar.original`
（320742 字节），而 target 已于 11:56 被重新打包。进程仍运行在构建目录归档上，
标准输出和错误连接临时会话管道，旧包装器日志还被测试启动覆盖。
这些证据支持构建改写运行归档导致实例失效的判断；旧异常输出未保留下来，
无法还原最初的具体类加载异常。直接原因已确认是 learning HTTP 实例失效。

另一个放大因素是看板统计客户端没有短时限配置，无法在浏览器 30 秒超时前可靠降级。
前端也存在重复弹出同一请求错误、管理页加载 Promise 未捕获的问题。

## 实际修改

1. `scripts/run-services.sh`：启动前复制独立 JAR 快照到 `.runtime/services/`，
   独立进程会话运行，stdout/stderr 追加到 `logs/<service>.log`。
   支持指定单个服务 start/stop/restart/status；停止只匹配监听进程。
   就绪检查从“端口存在”改为真实 HTTP 响应；探针走内部鉴权，正常返回 403。
2. `.gitignore`、`.dockerignore` 排除运行快照；运维手册说明快照不能在使用期间清理。
3. user 的三个看板 Feign 客户端设置连接 1 秒、读取 3 秒超时，
   配合已有指标级降级，服务不可用的指标保持 unavailable/null，不伪装为 0。
4. Axios 保留原有 30 秒配置，超时改为可理解的中文提示，并保留错误类型。
5. 两个管理员页面捕获加载失败，显示错误和重试入口，正常结束 loading。
6. 教师学情与问答列表避免重复通知已经由统一拦截器提示的错误。
7. 修复问答监管模板引用未定义 `userMap` 时的渲染错误，名称缺失时回退用户 ID。

已重新打包并以独立快照部署 learning 和 user；其他服务未重启。
本次没有修改业务表、索引、订单或学习记录。
